# Runtime contracts (G6)

The harness accepts `.vers/config.toml` in the candidate root. `version = "0.1"` and `timeout_seconds` (1–3600) are required in the supplied example; a missing file uses defaults. `runtime` is an array of cases with `name`, `argv`, `expected_exit`, `stdout`, and `stderr`. The optional `[checks]` table accepts only `"required"` and `"conditional"`; format, compile, clippy, tests, build, runtime and security must remain required. Miri, fuzz and coverage may be conditional or required. Their applicability and execution are not established by the MVP and are reported BLOCKED. Unknown keys and invalid types are errors. Each case runs without a shell from the snapshot root; expected stdout and stderr are exact UTF-8 byte strings. Use independent expected outputs and include valid and invalid behavior. Missing runtime cases BLOCK verification. Commands execute with normal host privileges; no sandbox or output redaction is provided.

The CLI fixture demonstrates help and an invalid input; the library fixture runs a consumer-facing example and checks its output. Add checks for filesystem effects, startup/shutdown or HTTP responses using a dedicated, isolated test driver as a runtime command; v0.1 has no built-in filesystem or HTTP assertions. Embedded systems need an approved device/emulator and a target-specific driver. Explicitly block cases that cannot be executed. A passing command is evidence only for its configured assertions.

Reports are placed in `.vers/reports/<run-id>/`; raw stdout/stderr can contain sensitive data. Cargo runs offline but build scripts and runtime commands can still access networks unless the surrounding environment prevents it. Set time/resource restrictions and appropriate credentials outside the harness.

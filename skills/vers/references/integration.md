# Installation and evidence

Install `skills/vers` using a host's skill installer and restart or reload the host. `$vers` works only when that host discovers the installed skill. The verifier can also be run directly with `skills/vers/scripts/verify.sh`; it builds the included Rust CLI with Cargo and locked dependencies. Dependencies must already be cached for the wrapper's offline build, or the CLI must be built in an environment with registry access beforehand. `cargo run --manifest-path skills/vers/Cargo.toml -- --help` shows the CLI syntax.

The harness copies the candidate apart from root `.git`, root `target`, and `.vers/reports`, rejects symlinks and special files, and hashes paths, file content and Unix permissions with SHA-256 before and after copying and executing. Tracked files in excluded output paths block discovery. Candidate configuration is included in the source hash; the report also records its own SHA-256. HEAD, Git porcelain status, tools, checks, evidence paths and verdict accompany the digest. This is a snapshot of included files, not a Git commit or a security boundary. Excluded paths must contain only build/report outputs; if the project reads them as source inputs, do not rely on the run. External files, environment, dependencies, services and toolchain are not captured by the source hash. Unsandboxed code could modify or restore inputs while running; use isolated, read-only mounts and a separate trusted verifier/report location for adversarial candidates. Do not trust evidence controlled by the candidate. The harness does not enforce implementer/verifier separation or orchestrate repair agents.

The report is JSON plus a human summary and per-command stdout/stderr logs. Exit codes: 0 PASS, 1 FAIL, 2 BLOCKED or configuration/infrastructure error (which may prevent report creation). Failure takes precedence over blocked status, and blocked checks remain visible. A runtime case checks exact exit/stdout/stderr. `--report` prints the latest JSON report, and `--report PATH` prints a specified report; neither re-verifies it. Check `source_unchanged` and rerun on every edit. Reports are validated against the bundled schema by a fail-closed validator supporting the vocabulary used in that schema, plus internal verdict invariants; this is not a general-purpose JSON Schema implementation.

VERS v0.2 can accept independent review records for previously blocked gates. See [review-evidence.md](review-evidence.md) for the two-run workflow, policy, bundle, artifact requirements and critical trust limitations. Without qualifying evidence or explicit operator attestation of its provenance, those gates remain BLOCKED. `--strict` adds an unimplemented check and cannot PASS. A pass is evidence of the specified checks and accepted reviews, not proof of software correctness. Reviewers must separately establish adequate coverage, applicability and independence.

Run `python3 skills/vers/tests/test_harness.py` from the library root to exercise real Cargo projects and synthetic review records. Tests require Git, Cargo, rustfmt, Clippy, `timeout`, Python 3, and cached verifier dependencies. The fixture cases execute only local, purpose-built code; their fabricated reviews test the protocol, not real independent review or defect detection. Advisory, unsafe-pointer/Miri and concurrency analysis are not implemented by the harness.
